## 4. หลักการและสมการสำคัญ

### 4.1 ภาพ SAR และ backscatter

SAR (Synthetic Aperture Radar) ส่งคลื่นไมโครเวฟลงมาเองแล้ววัดพลังงานที่สะท้อนกลับ จึงถ่ายได้ทั้งกลางวันกลางคืนและทะลุเมฆ เหมาะกับช่วงน้ำท่วมซึ่งมักมีเมฆปกคลุม Sentinel-1 ใช้ C-band ความยาวคลื่นประมาณ 5.6 ซม.

| พื้นผิว | กลไกการสะท้อน | ลักษณะบนภาพ |
|---|---|---|
| ผิวน้ำนิ่ง | สะท้อนแบบกระจกเงา ออกไปจากดาวเทียม | มืดมาก |
| ดินขรุขระ ทุ่งหญ้า | กระเจิงจากผิว (surface scattering) | เทาปานกลาง |
| ป่า พืชสูง | กระเจิงในเรือนยอด (volume scattering) | VH สว่าง |
| อาคาร ต้นไม้ที่มีน้ำท่วมโคน | สะท้อนสองครั้ง (double bounce) | VV สว่างมาก |

Polarization บอกทิศการสั่นของคลื่น **VV** คือส่งแนวตั้งรับแนวตั้ง ไวต่อความขรุขระของผิว ส่วน **VH** คือส่งแนวตั้งรับแนวนอน ไวต่อโครงสร้างของพืช

### 4.2 หน่วยเดซิเบล

ค่า backscatter coefficient $\sigma^0$ มีช่วงกว้างมาก จึงแสดงเป็นเดซิเบล (dB)

$$\sigma^0_{dB} = 10\log_{10}(\sigma^0) \qquad\Longleftrightarrow\qquad \sigma^0 = 10^{\sigma^0_{dB}/10}$$

จำง่าย ๆ: −3 dB คือพลังงานเหลือครึ่งหนึ่ง และ −10 dB คือเหลือหนึ่งในสิบ การหาค่าเฉลี่ยและการกรองภาพต้องทำบนค่า linear ส่วนการแสดงผลและการหาผลต่างทำบน dB

### 4.3 การกรอง speckle

Speckle คือสัญญาณรบกวนลักษณะเม็ดเกลือพริกไทย ตัวกรองแบบค่าเฉลี่ยเคลื่อนที่ขนาด $n \times n$ จุดภาพ คำนวณบนค่า linear

$$\hat\sigma^0 = \frac{1}{n^2}\sum_{i=1}^{n^2}\sigma^0_i$$

บทเรียนใช้ $n = 7$ (70 ม.) หน้าต่างใหญ่ขึ้นภาพเรียบขึ้น แต่ขอบของวัตถุจะเบลอ

### 4.4 Change detection

$$\Delta\sigma^0_{dB} = \sigma^0_{flood,dB} - \sigma^0_{ref,dB} = 10\log_{10}\left(\frac{\sigma^0_{flood}}{\sigma^0_{ref}}\right)$$

ผลต่างใน dB เท่ากับอัตราส่วนในหน่วย linear ค่าที่ติดลบมากหมายถึง backscatter ลดลงมาก ซึ่งเป็นลักษณะของพื้นที่ที่เปลี่ยนจากแห้งเป็นมีน้ำ จุดภาพจัดเป็นน้ำท่วมเมื่อ $\Delta\sigma^0_{dB} < T$ โดย $T$ คือ threshold

### 4.5 วิธี Otsu

เลือก threshold ที่ทำให้ความแปรปรวนระหว่างสองกลุ่มสูงสุด

$$t^* = \arg\max_t\ \omega_0(t)\,\omega_1(t)\,[\mu_0(t)-\mu_1(t)]^2$$

โดย $\omega_0, \omega_1$ คือสัดส่วนจุดภาพของสองกลุ่ม และ $\mu_0, \mu_1$ คือค่าเฉลี่ยของแต่ละกลุ่ม วิธีนี้ทำงานดีเมื่อ histogram มีสองยอดชัดเจน

### 4.6 การคำนวณพื้นที่

$$A_{rai} = \frac{N \times a_{pixel}}{1{,}600}$$

โดย $N$ คือจำนวนจุดภาพ $a_{pixel}$ คือพื้นที่หนึ่งจุดภาพ (100 ตร.ม. ที่ความละเอียด 10 ม.) และ 1 ไร่ = 1,600 ตร.ม. หนึ่งจุดภาพจึงเท่ากับ 0.0625 ไร่ และ 1 ตร.กม. = 625 ไร่

ประชากรในพื้นที่น้ำท่วมคำนวณแบบถ่วงน้ำหนักด้วยสัดส่วนที่ถูกน้ำท่วม $f_i$ ของแต่ละจุดภาพประชากร

$$P_{exposed} = \sum_i P_i \times f_i$$

### 4.7 Machine learning

**Random Forest** สร้างต้นไม้ตัดสินใจจำนวนมากแบบขนานกันแล้วลงคะแนน (bagging) จุดแยกเลือกจากค่า Gini impurity

$$G = 1 - \sum_k p_k^2$$

**XGBoost** สร้างต้นไม้ต่อเนื่องกัน ต้นใหม่แก้ความผิดพลาดของต้นก่อนหน้า (boosting)

$$F_m(x) = F_{m-1}(x) + \eta\,h_m(x)$$

โดย $\eta$ คือ learning rate

### 4.8 ตัวชี้วัดความถูกต้อง

| | ทำนาย: ท่วม | ทำนาย: ไม่ท่วม |
|---|---|---|
| **อ้างอิง: ท่วม** | TP | FN (ตรวจขาด) |
| **อ้างอิง: ไม่ท่วม** | FP (ตรวจเกิน) | TN |

$$OA = \frac{TP+TN}{N} \qquad Precision = \frac{TP}{TP+FP} \qquad Recall = \frac{TP}{TP+FN}$$

$$F1 = \frac{2 \cdot Precision \cdot Recall}{Precision + Recall} \qquad IoU = \frac{TP}{TP+FP+FN} \qquad \kappa = \frac{p_o - p_e}{1 - p_e}$$

สำหรับ ป.โท: McNemar's test ใช้เปรียบเทียบสองโมเดลบนชุดทดสอบเดียวกัน

$$\chi^2 = \frac{(|b - c| - 1)^2}{b + c}$$

โดย $b$ และ $c$ คือจำนวนจุดที่มีเพียงโมเดลใดโมเดลหนึ่งตอบถูก

| Threshold | 246,876 | | |
| Random Forest | 280,018 | +13.4% | 91.3% |
| XGBoost | 279,961 | +13.4% | 91.0% |

- **ความถูกต้องสูงบนชุดทดสอบ ไม่ได้แปลว่าแผนที่จะเหมือนกัน:** F1 = 0.955 แต่แผนที่ ML ให้พื้นที่มากกว่า threshold ร้อยละ 13.4 และจุดภาพเกือบร้อยละ 9 ถูกจัดต่างกัน เพราะชุดทดสอบมีเฉพาะจุดที่ "มั่นใจ" ส่วนแผนที่ทั้งภาพต้องตัดสินจุดกำกวมใกล้ค่า threshold ด้วย
- **สองโมเดล ML ให้พื้นที่เกือบเท่ากัน** (ต่างกัน 57 ไร่) ความต่างหลักจึงอยู่ระหว่าง "วิธี threshold" กับ "วิธี ML" ไม่ใช่ระหว่างอัลกอริทึม
- **ทำไม ML ให้พื้นที่มากกว่า:** โมเดลตัดสินจากความมืดในวันน้ำท่วมเป็นหลัก จึงจัดพื้นที่ที่มืดอยู่แล้วในภาพอ้างอิง (เช่น นาที่ขังน้ำในเดือนมกราคม) เป็นน้ำท่วมด้วย และโมเดลทำนายจากแบนด์ดิบทีละจุดภาพ จึงมีจุดกระจายตามขอบแปลงและแนวคลอง ดูตำแหน่งได้จากแผนที่ agreement

**McNemar's test (ป.โท)**

| | XGBoost ถูก | XGBoost ผิด |
|---|---|---|
| **RF ถูก** | 5,629 | 60 |
| **RF ผิด** | 31 | 205 |

- $\chi^2$ = 8.62, p = 0.0033 สองโมเดลต่างกันอย่างมีนัยสำคัญทางสถิติที่ระดับ 0.05
- **นัยสำคัญทางสถิติไม่เท่ากับความสำคัญในทางปฏิบัติ:** การทดสอบดูเฉพาะ 91 จุดที่สองโมเดลตอบต่างกัน (60 กับ 31) จากทั้งหมด 5,925 จุด ความถูกต้องต่างกันเพียง 0.5 จุดร้อยละ และแผนที่ให้พื้นที่เกือบเท่ากัน เมื่อตัวอย่างมีจำนวนมาก ความต่างเล็กน้อยก็มีนัยสำคัญได้ จึงต้องรายงานขนาดของความต่างควบคู่กับค่า p เสมอ
- ทั้งสองโมเดลตอบผิดตรงกันถึง 205 จุด มากกว่าจุดที่ตอบต่างกัน แปลว่าความผิดพลาดส่วนใหญ่มาจากข้อมูลและ label ไม่ใช่จากอัลกอริทึม

**การประมาณพื้นที่แบบ Olofsson (ป.โท)**

| ชั้นตามแผนที่ RF | สัดส่วนพื้นที่ (W) | ตัวอย่าง | อ้างอิงบอกว่าท่วม |
|---|---|---|---|
| ท่วม | 0.319 | 500 | 404 |
| ไม่ท่วม | 0.681 | 500 | 19 |

- พื้นที่จากการนับจุดภาพบนแผนที่ RF คือ 280,018 ไร่ พื้นที่ที่ปรับแก้แล้วคือ **249,009 ± 13,948 ไร่** (ช่วงความเชื่อมั่น 95%)
- **อ่านตารางอย่างไร:** ในชั้นที่แผนที่บอกว่าท่วม ข้อมูลอ้างอิงเห็นด้วย 404 จาก 500 จุด (ร้อยละ 80.8) แผนที่จึงตรวจเกินเกือบหนึ่งในห้า ส่วนในชั้นไม่ท่วม มี 19 จุด (ร้อยละ 3.8) ที่ข้อมูลอ้างอิงบอกว่าท่วม วิธีนี้นำความผิดพลาดทั้งสองแบบมาปรับแก้พื้นที่ และให้ช่วงความไม่แน่นอนมาด้วย
- **ข้อจำกัดของการสาธิตนี้:** ข้อมูลอ้างอิงที่ใช้คือแผนที่ threshold เอง พื้นที่ที่ปรับแก้แล้วจึงกลับมาใกล้ 246,876 ไร่ตามที่ควรเป็น ผลนี้แสดงว่าวิธีคำนวณทำงานถูกต้อง แต่ไม่ได้ยืนยันว่า threshold ถูก ในงานจริงต้องใช้ข้อมูลอ้างอิงจากภาคสนามหรือการแปลด้วยสายตา

## 6. ข้อควรระวังในการแปลผล

### 6.1 ค่า nodata ของไฟล์ข้อมูล

ไฟล์ GeoTIFF ใน `data/` เก็บจุดภาพนอกขอบเขตอำเภอเป็นค่า **0** ไม่ใช่ค่า nodata (ประมาณร้อยละ 39 ของกรอบภาพ) สำหรับภาพ SAR ค่า 0 หมายถึง 0 dB ซึ่งเป็นค่าที่เป็นไปได้จริง ฟังก์ชันใน `sarflood_utils.py` จึงตัดข้อมูลด้วยขอบเขตอำเภอทุกครั้งที่อ่านไฟล์ ผลใน notebook 01–05 จึงถูกต้อง

ถ้านิสิตเปิดไฟล์เหล่านี้ด้วยโปรแกรมอื่น เช่น QGIS หรืออ่านด้วย `rasterio` โดยตรง ต้องตัดด้วย `boundary_amphoe.geojson` ก่อนคำนวณสถิติ มิฉะนั้นจะได้ค่าเฉลี่ยสูงเกินจริงและ histogram ที่มีแท่งสูงที่ 0 dB บทเรียนสำหรับงานวิจัยคือ **ตรวจค่า nodata และดู histogram ก่อนคำนวณสถิติทุกครั้ง**

### 6.2 ข้อจำกัดของวิธีการ

- **ไม่มีข้อมูลอ้างอิงภาคสนาม** threshold เลือกจากหลักฐานในภาพเอง และ ML เรียนจาก pseudo-label ผลลัพธ์ทั้งหมดจึงยังไม่ได้ตรวจสอบกับน้ำท่วมจริง
- **ผลไวต่อ threshold** พื้นที่น้ำท่วมอยู่ระหว่างประมาณ 214,000 ถึง 290,000 ไร่ เมื่อ threshold อยู่ระหว่าง −4 ถึง −2 dB
- **ภาพอ้างอิงถ่ายเดือนมกราคม** ซึ่งเป็นฤดูแล้งหลังเก็บเกี่ยว สภาพพืชและความชื้นดินต่างจากเดือนตุลาคม และพื้นที่เพาะปลูกร้อยละ 8.68 ที่มืดอยู่แล้วในภาพอ้างอิงจะตรวจไม่พบว่าท่วม
- **น้ำท่วมใต้พืชและในเขตอาคาร** ทำให้ภาพสว่างขึ้น วิธีที่จับเฉพาะการมืดลงจึงมองไม่เห็น ตัวเลขสิ่งปลูกสร้างและประชากรจึงน่าจะต่ำกว่าจริง
- **ภาพเดียวไม่ใช่ช่วงน้ำสูงสุด** Sentinel-1 ดวงเดียวถ่ายซ้ำทุก 12 วัน จึงอาจพลาดขอบเขตน้ำท่วมสูงสุด
- **ข้อมูลประกอบไม่ตรงปี** WorldCover และ GHSL เป็นปี 2020 ส่วนเหตุการณ์คือปี 2017
- **ขอบเขตการปกครอง** ใช้ FAO GAUL ซึ่งหยาบกว่าข้อมูลทางการของไทย พื้นที่ที่คำนวณจากราสเตอร์ 10 ม. (878,820 ไร่) จึงต่างจากพื้นที่ของโพลิกอน (882,226 ไร่) เล็กน้อย
